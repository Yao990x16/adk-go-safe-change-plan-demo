# CPU 持续偏高（虚构演示用通用 Runbook）

## 可能原因
- 可能是请求负载增加、热点计算或资源配额不合适；缺少负载曲线和性能剖析，不能确定根因。

## 建议变更计划
- 人工比较负载与 CPU 基线；仅在容量与配额确认后，提出单个副本的小范围资源调整。回滚条件：延迟、错误率或资源争用比变更前恶化；回滚方式：由人工恢复原资源配置并观察基线。

## 风险与回滚方式
- 资源调整可能挤占其他工作负载；人工先记录原配置，只改变一个变量，观察窗口与停止阈值必须在审批时确定。

## 需要人工确认的事项
- 人工确认 CPU 指标口径、持续时间、流量曲线、容量余量和资源配置；当前快照不足以证明 CPU 是崩溃原因。
